# BNOW.NET 48-hour execution program — index (2026-09-05)

**What this is.** The operator has a large budget of frontier-model agent credits to spend
over the next 48 hours and one human reviewer (the operator). This index sequences the
CTO roadmap handoff (`docs/prompts/2026-09-05-cto-roadmap-handoff.md`) into agent sessions
that can run in parallel, names the model / effort / mode for each, and points at one
self-contained prompt file per step (`docs/prompts/2026-09-05-48h-NN-<slug>.md`). Every
step ends with a written report so the next step — or a rewritten prompt — can start cold.

**Status of this document.** Authored from a verified snapshot of `origin/main` @ `883e5e3`
plus the untracked handoff, read in full by eight parallel reader agents whose findings were
cross-checked against file:line evidence and then judged by an independent panel. Where the
readers found the handoff itself stale or wrong, §1 says so; the step prompts already carry
the corrections. The program is a living document: the operator rewrites later prompts at
each checkpoint from the reports of earlier steps (§6), and appends to the program log (§10).

**Binding scope for every session in this program** (also in `…-48h-COMMON.md`, which every
prompt reads first): planning sessions plan; execution sessions build code + tests on a
branch and open a PR; nothing deploys, changes a Vercel environment, writes production data,
spends money, edits the evaluation datasets under `docs/evals/analysis/` (except step 07's
two authorized new files: the dataset and its committed offline-results file), the scorer, the registry approvals, or the map lock without
a named operator authorization recorded in the decision log. Where the handoff says
DECISION, the session lists it (§2) — it never decides.

## 0. How to run the program

1. **H0 — operator kickoff (≈45 min, §5 Wave 0).** Answer the decision sheet (§2) — at
   least the items marked H0. Create the lane worktrees natively on the Mac (§4). Merge
   PR #47; resolve PR #48 per D1. Confirm the Neon key with one branch create/delete
   (§5 Wave 0). Paste the Wave 1 prompts into fresh sessions, one per lane.
2. **Each session is started INSIDE its worktree**, never in `~/code/bnow-net`:
   `cd /Users/go/code/bnow-net-worktrees/48h-<worktree>-20260905 && claude`, then paste the
   step prompt. (A session started in the main checkout has `main` as its working tree; if
   it forgets to `cd`, it edits and commits on `main` — six concurrent sessions make that a
   collision, not a hypothetical.) The session reads
   `docs/prompts/2026-09-05-48h-COMMON.md`, then its own prompt file, proves it is in the
   worktree (COMMON §1), opens a PROGRESS.md plan block (AGENTS.md operating protocol step 1),
   does the work on its step branch, and ends with the closing report the prompt names. Reports go to
   `docs/reviews/` under the name the prompt gives, committed on the same branch.
3. **Checkpoints (§6).** The operator reads reports, merges PRs in the order §6 gives (migration
   PRs have a fixed order, §4), records decisions as decision-log entries (the reconcile
   session drafts them), and rewrites or confirms the next wave's prompts. A prompt marked
   *SKETCH* in its header must be rewritten from the named upstream report before use.
4. **H48 — close.** Step 26's final audit issues a per-PR deploy go/no-go; step 27 (operator)
   deploys only through the new release checklist and only what needs no new cap env.
   Nothing in this program deploys before that point.

Model roster used throughout (§3 has the rules): **Fable** = architecture plans and
adversarial audits (plan mode / ultracode); **Astra** = the second frontier model, used where
independence from Fable's reasoning is the point (second-opinion audits) — substitute Fable
if Astra is unavailable; **Opus** = implementation PRs with tests; **Sonnet** = inventory,
docs, and mechanical edits with a verification script.

## 4. Lanes, worktrees, migration order

Create worktrees **natively on the Mac** (never from a Cowork/remote mount — see §8), from a
fresh `origin/main`. One worktree per step that runs concurrently — two sessions can never
share a checkout:

```
cd /Users/go/code/bnow-net && git fetch origin && git pull --ff-only && git push origin main
# (push first: worktrees are cut from origin/main and must see the current program docs)
for wt in ws2-routing ws2-provider ws2-remap ws3-conflict ws3-gazetteer ws1-injection ws1-adjudication ws4-ops audit-ws2 audit-ws3; do
  [ -d ../bnow-net-worktrees/48h-$wt-20260905 ] || \
    git worktree add ../bnow-net-worktrees/48h-$wt-20260905 -b 48h/$wt-20260905 origin/main
done
git worktree list   # must show no /sessions/ paths
for wt in ws2-routing ws2-provider ws2-remap ws3-conflict ws3-gazetteer ws1-injection ws1-adjudication ws4-ops audit-ws2 audit-ws3; do
  [ -d ../bnow-net-worktrees/48h-$wt-20260905/node_modules ] || \
    cp -Rc node_modules ../bnow-net-worktrees/48h-$wt-20260905/node_modules
done   # APFS clone of the main checkout's node_modules: near-instant, no extra disk until
       # modified; identical lockfile at every worktree. A PR that changes dependencies
       # re-runs `npm install` in its own worktree only.
```

## 6. Checkpoint protocol (what the operator does each time)

1. Read every closing report produced since the last checkpoint (`docs/reviews/*-2026-09-0*.md`
   named in the step prompts). Each report ends with a **"Handoff"** section: what changed,
   test numbers, decisions needed, and what the next prompt must know.
2. Merge PRs in the order the wave says. Migration PRs: rebase, `npm run db:generate` check,
   then merge. Never merge a PR whose report shows red tests or missing fork-itest numbers.
3. Sign decisions: step 01 drafts decision-log entries in `docs/reviews/DECISION-ENTRIES-DRAFT-2026-09-05.md`;
   copy the signed ones to AGENTS.md's decision log (append at end of file until step 15
   lands, then under `## Decision log`). Spend / production-write / dataset-write items are
   never implied: an unsigned draft means "not authorized".
4. Rewrite the next wave's SKETCH prompts from the reports (the sketch says which report).
5. Append a program-log line to §10 (time, merged, decided, rewritten, blocked).

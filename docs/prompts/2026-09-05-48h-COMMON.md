## 4. How to work

1. Append a plan block to `docs/PROGRESS.md` in the observed shape
   (`## YYYY-MM-DD ~HH:MMZ — <title> (planned block)`, numbered list) before editing. On a
   rebase conflict in PROGRESS.md keep BOTH sides verbatim in timestamp order (2026-08-20
   precedent); never drop another session's block. `.gitattributes` marks PROGRESS.md and
   BLOCKERS.md `merge=union`, so a local rebase normally resolves this by itself — check the
   result reads in date order before continuing.
2. Cut a step branch from the worktree branch, DASH-separated: `48h/<worktree>-20260905-<step-slug>`
   (a slash after the lane name collides with the worktree branch ref — git refuses it).
3. Build with tests. Every parser/adapter/scorer change gets fixture-based tests; every
   refusal path gets a "refused before `tryReserve` / before client construction" pin where
   spend is involved; every gated page asserts the gate ran before its first query.
4. Adversarial self-review of the diff: edge cases, secret leakage (`git diff | grep -iE
   'key|secret|token|postgres://'`), claim-to-source, rate-limit safety, ruling compliance.
5. `npm run typecheck && npm run lint && npm test` green before every commit. Migration or
   DB-touching PRs also run the relevant `*.itest.ts` on a disposable fork and report the
   numbers. Commit messages: `area: imperative summary`, small and atomic.
6. Open the PR (or leave the branch pushed and say so if `gh` is unavailable) with a body
   that mirrors the closing report's Built / Tests / Rulings sections.
7. **AGENTS.md write-lock:** unless your prompt is step 01, 02, 03, 15 or 25, do not edit `AGENTS.md`
   except to correct in place the single standing line your PR makes wrong (e.g. the
   `drizzle/` range in the directory map). Put every other proposed standing-text correction
   (file:line, before → after) and your proposed decision-log entry in a "Proposed AGENTS.md
   changes" block of your closing report; step 25 applies them. `docs/OPEN-TASKS.md`: edit
   only the status lines of the tasks your step touches, and rebase before merge.
8. **Any local `next build && next start` bound to a Neon fork** (remap dry run, authz itest,
   pipeline demo) runs with `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` and `POSTMARK_SERVER_TOKEN`
   BLANK and `LLM_DISABLE=1` — `withCronRun`'s start path runs the map watchdog outside vitest
   and can email from fork state (`src/integration/authz-page-gate.itest.ts` `serverEnv()` is
   the pattern). Copy it; never start a fork-bound server with the production `.env.local`
   as-is. **Until PR #52 (step 09) merges:** `.env.local` carries an `ANTHROPIC_API_KEY`
   (D2 = B) and, on `main` before #52, `getProvider()` selects the Anthropic provider whenever
   `OPENAI_API_KEY` is blank — a path with no `SpendGuard`, no registry approval and no
   metering. (Correction from step 09's report: that path DID honour `LLM_DISABLE=1` via
   `assertLlmEnabled` — the kill-switch was never the gap; the missing guard and identity
   were.) So until #52 is on `main`, any script, test or server run with `OPENAI_API_KEY`
   blanked also blanks `ANTHROPIC_API_KEY`; after #52 the key-alone branch no longer exists.
9. **Decisions that authorize spend, production writes, or a write under `docs/evals/analysis/`
   are never implied.** If the decision-log entry is missing or unsigned, print
   `AWAITING AUTHORIZATION: <id>` in your report, leave the PR marked HELD, and stop before
   any run.

**Design decisions worth stating, because they are not restatements of the plan.**

- **`"unscorecarded"` is a new literal, not `"stub"`.** `"stub"` means offline/kill-switch. A
  refused *model* and an absent *key* are different operator situations and must stay
  distinguishable in `ask_usage`; the precedent is the budget path, which writes `"budget"`.
- **`answer.ts` degrades, `answer-stream.ts` throws.** `answerFromEvidence` is the user surface
  (ruling 9). `streamAnswer` is not, and returning a fabricated `StreamOutcome` would be worse than
  a pre-call throw — the one class its own contract already allows ("Throws ONLY pre-call"). Because
  `answer.ts` gates first, the throw is unreachable from the product path and is pinned as defence
  in depth for direct callers.
- **The suite names are constants.** A typo in a suite literal makes `hasScorecard()` false
  everywhere and silently degrades *every* answer — a failure mode that would look like an outage,
  not a bug. `registry.test.ts` now pins each constant against the registry entry that carries it,
  and pins that no model is scorecarded for both.
- **`autoPolicyReason` is extracted and exported** so the `auto_env_override` branch keeps a test.
  Under the current registry that branch is unreachable through `route()` (gpt-5 is the only
  `v2-k60` entry, so every possible override is unscorecarded); testing the reason only through env
  would have deleted the coverage instead of moving it. Precedence is deliberate:
  `auto_scorecard_missing` outranks the baseline/override distinction because it is the
  consequential fact — the pipeline will not dispatch that model at all, so recording
  `auto_env_override` would describe a paid run that never happens.

## Debt and risks

- **The paid answer-model matrix is now blocked by construction** (R14 above). This is the single
  most consequential consequence of the PR and it was not called out in PLAN §4.3. It is *safe* —
  the harness aborts loudly and names the provider — but a session that tries to run the matrix
  will hit it immediately. Read R14 before scheduling one.
- **`auto_env_override` is unreachable through `route()` today.** Not a defect: gpt-5 is the only
  `v2-k60` entry, so every possible override is unscorecarded. It becomes reachable the moment a
  second answer model is scorecarded. The branch is kept and tested on the pure function precisely
  so this does not decay into dead code nobody notices.
- **The streaming gate is unreachable from production.** `answer.ts` gates first. It is pinned by
  direct calls to `streamAnswer`, and its value is that a future reordering of `answer.ts` cannot
  silently open the path. Stated so a reviewer does not read the pin as end-to-end coverage.
- **The legacy pipeline (`ASK_PIPELINE=legacy`) is deliberately NOT gated.** It reads `OPENAI_MODEL`
  (default `gpt-4o-mini`, which carries no scorecard of any suite), so gating it would break the
  rollback path outright. The rollback exists to restore known-good behaviour during an incident;
  making it refuse would be worse than the hole. Recorded, not fixed.
  **Amended 2026-09-09 (step 23, WS2-F06 / OPEN-TASKS #110): this bullet understated the hole.**
  The missing scorecard gate was not the only thing absent from that path — at the time this
  report was written `legacyAnswer` reached the paid dispatch with **no SpendGuard at all**: no
  `askGuardFromEnv()`, no `init()`, no `tryReserve()`, no `record()` and no `provider_usage` row,
  so it did not fail closed when `LLM_SPRINT_USD_CAP` / `ASK_USD_CAP_DAILY` are unset (ruling 4)
  and its spend was invisible to the ledger. That was pre-existing since `cea8cac` (2026-07-11),
  not caused or widened by PR #67, and it is fixed in step 23's own PR (reserve before the call,
  degrade to the deterministic cited-claims answer with provider `"budget"` on refusal, meter
  after the call and before any body interpretation). The scorecard-gate exemption above is
  unchanged and still stands.
- **The gate reads the registry, not an eval result.** `hasScorecard()` is true because a human
  wrote a `scorecard:` block. The gate can only be as honest as that block — mutation M9 shows the
  whole baseline collapses if it is edited. It is not a substitute for the registry review that
  adds an entry.
- **`console.warn` fires per request on a gated path.** Intentional (an operator who set an
  override must see why answers changed) and consistent with the rerank budget warn, but a
  long-lived override would be noisy in the runtime log. The `runtime_logs` drain landed in #64 is
  inert (`LOG_DRAIN_SECRET` unset), so nothing accumulates today.
- **Another session checked out the lane branch `48h/ws2-routing-20260905` in this worktree while
  this step was running**, replacing the working tree after the gate commit had landed. Nothing was
  lost — the step branch was already committed and pushed and the untracked report survived — but a
  session that had uncommitted work at that moment would have. Recorded because the 48-hour program
  runs several sessions against one worktree per lane and the collision is invisible until a
  `git grep` returns the wrong tree. Mitigation used here: commit early, push early, and re-verify
  every asserted `git grep`/count on the correct branch before writing them down (which is how it
  was caught).
- **`provider` remains a bare `string` on `AskAnswerV2`.** Nothing type-checks the set of literals;
  the four consumers agree by test, not by type. A discriminated union would be a separate,
  wider PR.

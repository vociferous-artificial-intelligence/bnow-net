# Playbooks — what this folder is, in plain terms

A playbook is a written, repeatable way of doing a piece of business work. Each one in this
folder is a set of step-by-step instructions that either an AI agent or a person can follow,
producing a written report at the end of every step so the next step has something solid to
build on. The playbooks are the same in every one of our projects; what differs per project
is the results they produce.

There is one playbook so far:

**`rollout/` — Brand, marketing and design for a new application.** It takes a product that
has already been built (usually from a founder's vision, with little or no customer input
yet) and works through, in order: finding out what real buyers need; researching the
competition; deciding what we stand for and what we charge; giving the product a visual
identity; writing the website and sales materials; measuring the launch. It exists because
the natural instinct is to do these in the wrong order — build first, design second, talk to
customers last — and the playbook makes the right order hard to skip.

## Two folders, two purposes

- **`docs/playbooks/rollout/`** (this folder) is the *recipe*. It never contains findings about
  this project. Copy it to another project as-is.
- **`docs/rollout/`** is the *cooking* — this project's reports produced by following the
  recipe: the gap register, interview write-ups, research, decisions, sign-offs. Never copy
  it to another project.

## How the work is organised

Each step in the playbook is labelled by who does it:

- **AGENT** steps are research and drafting an AI can do on its own from a written prompt —
  reading our documents, studying competitors' websites and public records, drafting
  positioning options, writing website copy, specifying what to measure. The prompt says
  exactly what to read, what to produce and where to save it.
- **OPERATOR** steps are the ones only a person can do — interviewing buyers, choosing between
  options, testing a message on real people, signing off a launch. Each comes with a short
  instruction sheet and a fill-in-the-blanks report so the outcome is recorded in a form the
  next step can use.

Every step's output is a dated document with a standard header stating what it read and
what it feeds. That is what lets a new person or a fresh agent pick up the work mid-way.

## Where to start

Read `rollout/README.md`, then `rollout/PLAYBOOK.md`, which lists all the steps in order
with what each needs and produces. The first step, A0, scores the project against the whole
sequence and writes a **gap register** — the honest list of what is done, half-done and
missing. That register is the plan; work it from the first gap.

The one rule that is not negotiable: nothing about positioning, identity or copy is treated
as final until at least eight buyer interviews have been done and written up. Drafts made
before that are kept but marked provisional.
